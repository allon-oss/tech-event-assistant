# 科技创业活动观察与跟进助手

从报名与签到数据中快速观察活动表现，并沉淀后续关系跟进。

**V0.2 · 本地 CSV 跟进工作流**

当前展示数据为 **Synthetic Demo Data，仅用于产品流程验证**。活动名称为「创业者交流」。本项目帮助主办方回答报名与到场规模、参与者结构、渠道表现、会后跟进四个问题。

## 本地运行

当前电脑的项目虚拟环境已经准备好。在项目目录打开 PowerShell，运行：

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

打开 <http://127.0.0.1:8501>。如果服务已经运行，直接访问即可；在自行启动的终端按 `Ctrl+C` 可以停止。若 8501 被其他应用占用，可在命令末尾加 `--server.port 8502`，然后访问对应端口。

默认只监听本机 `127.0.0.1`，不对局域网开放。Streamlit 使用统计已关闭。应用不调用大模型 API，不需要 API Key。

### 在其他电脑重新安装

建议使用 Python 3.12。`.venv` 与本机 Python 关联，不要复制它到其他电脑，也不要提交它。安装 Python 后，在项目根目录执行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

如果电脑使用 `python` 而不是 `py` 命令，第一行可替换为 `python -m venv .venv`。当前开发电脑没有全局 Python，现有环境由 Codex 附带的 Python 创建；若该运行时移动或删除，需要用新安装的 Python 重建环境。

已验证环境：Python 3.12.14、Streamlit 1.65.0、Pandas 3.0.6、Plotly 6.9.0。三个直接依赖固定在 `requirements.txt` 中。

## 页面与操作

从侧边栏选择三个页面。窗口较窄时，点击左上角箭头展开导航。

- **活动总览**：六个 KPI、指标解释和后续页面指引。
- **活动观察**：身份构成、创业 / 关注方向、报名渠道表现，恰好三个 Plotly 图。渠道图中蓝色柱形对应左轴人数，棕色折线对应右轴到场率。
- **关系跟进**：只显示已到场且有明确对接意向的对象。可按状态、身份、负责人筛选；多个条件同时生效。选择「全部」取消对应条件。没有匹配记录时显示提示。

跟进表默认按照待跟进、已初步建联、跟进中、已完成对接、暂不跟进排序，同一状态按报名编号排序。表格使用 Streamlit 原生 `st.data_editor`，固定行数。报名编号、姓名、身份、公司 / 项目、方向和意向只读；状态、负责人、下一步动作和备注可编辑。状态和负责人使用下拉选项。宽表可横向滚动，或点击表格全屏按钮查看。

操作流程：筛选对象 → 编辑单元格 → 按 Enter 或点击表格外提交单元格 → 点击「保存修改」。看到「跟进信息已保存」后才完成持久化。切换筛选、页面或刷新会丢弃未保存编辑。已保存数据驱动首页 KPI 和跟进页四个进度数字。

进行中的跟进须有负责人和具体动作；已完成对接或暂不跟进须清空负责人、填写动作「暂无」。有明确意向的暂停对象仍保留在跟进名单和明确对接价值总数中，方便后续重新跟进。

界面负责人使用虚构演示名「林舟」「小林」「Mia」。第一位负责人在界面使用别名映射，筛选仍匹配原始数据键，原 CSV 和数据字典保持不变。表格显示和 CSV 导出均使用界面别名。

## 保存、恢复与导出

`src/followup_store.py` 优先读取 `data/demo_tech_event_working.csv`；不存在时读取原始 `data/demo_tech_event.csv`。首次保存会创建 working 文件，后续保存更新该文件。原始 CSV 和原始数据字典均保持不变。

保存按 `attendee_id` 合并当前筛选结果的四个跟进字段，再检查完整记录、只读字段、合法枚举、编号与到场逻辑。保留全部 100 条报名记录。写入同目录临时文件成功后原子替换 working 文件，写入失败不覆盖已有文件。内容版本检查会拒绝已检测到的陈旧保存/恢复。持久化依赖磁盘 CSV，因此浏览器刷新和 Streamlit 重启均保留修改。working 文件损坏时显示错误，允许通过确认恢复回到基线，不会静默忽略错误数据。

「恢复演示数据」先显示影响说明；点击「确认恢复」才删除 working 文件并清除当前编辑器内容，重新加载 Demo；点击「取消」保留修改。该操作会丢弃已保存的演示修改，使用前应按需导出。

「导出最新跟进表」重新读取当前已保存的数据，导出全部明确对接价值对象，不受筛选影响。文件为 UTF-8 BOM CSV，包含九个中文业务列，使用界面负责人别名。未保存内容不会进入此按钮的导出。编辑器工具栏自带下载用于当前筛选表格，业务验收与交付请使用下方「导出最新跟进表」。

限制：CSV 适用于本地单用户流程，没有多人并发事务保障；多个标签页同时编辑应先刷新。原生表格的未提交单元格、未点击保存的编辑不持久化；手机或窄窗口需横向滚动，长备注建议进入单元格查看。当前版本没有自动保存或编辑历史。

## 数据加载与错误处理

`src/data_loader.py` 从项目位置定位 CSV，使用 UTF-8 / UTF-8 BOM 读取，校验 13 个必要字段、表格列数、重复编号、核心空值、允许值及到场与跟进逻辑。机构和备注允许缺失；待跟进任务必须有负责人和具体动作。

文件不存在、编码错误、没有报名记录、必要字段缺失或存在业务矛盾时，页面显示中文错误并停止统计，避免错误数据变为看似可信的 KPI。加载仅在内存中去除首尾空格，不写回原文件。

字段定义见 [data/DATA_DICTIONARY.md](data/DATA_DICTIONARY.md)。当前合成 CSV 不应替换为含个人信息的真实名单后直接公开提交。
