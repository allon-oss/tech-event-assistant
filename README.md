# 科技创业活动观察与跟进助手

用于科技 / 创业活动的 **观察 → 跟进 → 复盘**：从报名与签到数据观察活动表现，记录会后关系跟进，再结合人工观察整理复盘。

**V1.0 · 作品集 Demo · Local / Demo 双模式**

当前项目是作品集 Demo，全部内置数据为 **Synthetic Demo Data（合成演示数据）**，没有真实客户数据。人物、公司、项目和负责人均为虚构演示内容，不代表真实活动或业务成果。活动名称为「创业者交流」。暂未接入 LLM、Agent、RAG、数据库和登录系统，不需要 API Key。

## 本地运行

复盘当前默认使用可解释的规则 / 模板生成，不需要任何 API Key。统一入口为 `src.review_generator.generate_review(data, observations, backend='template')`，已为未来 LLM 生成预留扩展接口。`backend='llm'` 当前只抛出“尚未配置、尚未启用”的 `NotImplementedError`，不会请求外部服务；页面继续使用模板。以后接入 OpenAI、DeepSeek 等模型时，在 `src/llm_provider.py` 适配已有统计摘要与人工观察并返回 Markdown，无须重写页面和统计逻辑；真实调用的安全配置与启用方式需另行实现。

建议使用 Python 3.12。在项目目录创建独立环境并安装依赖。Windows PowerShell：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:APP_MODE = "local"
.\.venv\Scripts\python.exe -m streamlit run app.py
```

打开 <http://127.0.0.1:8501>。如果服务已经运行，直接访问即可；在自行启动的终端按 `Ctrl+C` 可以停止。若 8501 被其他应用占用，可在命令末尾加 `--server.port 8502`，然后访问对应端口。

默认只监听本机 `127.0.0.1`，不对局域网开放。Streamlit 使用统计已关闭。应用不调用大模型 API，不需要 API Key。

### Linux / macOS

在项目根目录执行：

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

已验证环境：Python 3.12.14、Streamlit 1.65.0、Pandas 3.0.6、Plotly 6.9.0。三个直接依赖固定在 `requirements.txt` 中。

## Local / Demo Mode

| 模式 | 选择方式 | 跟进与复盘保存 | 刷新 / 重启 |
| --- | --- | --- | --- |
| Local Mode | `APP_MODE=local`，未配置时的默认值 | 本地 working CSV 和 Markdown 草稿 | 已保存内容保留 |
| Demo Mode | `APP_MODE=demo` | 每个访问者独立的 `st.session_state` | 会话结束后重置，须提前下载 |

两种模式使用相同的校验、KPI、复盘模板和下载逻辑。Demo Mode 只读取原始合成 CSV，忽略磁盘上的 working CSV 和草稿；编辑数据、人工输入与保存稿仅属于当前会话，不使用共享可变缓存。不同访问者不能看到彼此修改。保存、恢复和下载都不写公共文件，原始 CSV 永远不被应用修改。

在 PowerShell 中设置 `$env:APP_MODE = "demo"` 后按上述命令启动，即可在本机预览 Demo Mode。Linux 使用 `APP_MODE=demo .venv/bin/python -m streamlit run app.py`。切换模式后重新启动服务。Demo 刷新会失去修改，这是会话演示的预期行为；CSV 下载使用本会话已保存跟进，Markdown 下载包含当前编辑正文和未保存修改。[Streamlit 会话说明](https://docs.streamlit.io/develop/api-reference/caching-and-state/st.session_state)

## 页面与操作

从侧边栏选择四个页面。窗口较窄时，点击左上角箭头展开导航，选择页面后可收起侧栏以便操作正文。

- **活动总览**：六个 KPI、指标解释和后续页面指引。
- **活动观察**：身份构成、创业 / 关注方向、报名渠道表现，恰好三个 Plotly 图。渠道图中蓝色柱形对应左轴人数，棕色折线对应右轴到场率。
- **关系跟进**：只显示已到场且有明确对接意向的对象。可按状态、身份、负责人筛选；多个条件同时生效。选择「全部」取消对应条件。没有匹配记录时显示提示。
- **活动复盘**：数据摘要、五项可选人工补充、可编辑草稿。无 API Key 也能生成、复制、保存和导出 Markdown。

跟进表默认按照待跟进、已初步建联、跟进中、已完成对接、暂不跟进排序，同一状态按报名编号排序。表格使用 Streamlit 原生 `st.data_editor`，固定行数。报名编号、姓名、身份、公司 / 项目、方向和意向只读；状态、负责人、下一步动作和备注可编辑。状态和负责人使用下拉选项。宽表可横向滚动，或点击表格全屏按钮查看。

操作流程：筛选对象 → 编辑单元格 → 按 Enter 或点击表格外提交单元格 → 点击「保存修改」。看到「跟进信息已保存」后才完成持久化。切换筛选、页面或刷新会丢弃未保存编辑。已保存数据驱动首页 KPI 和跟进页四个进度数字。

进行中的跟进须有负责人和具体动作；已完成对接或暂不跟进须清空负责人、填写动作「暂无」。有明确意向的暂停对象仍保留在跟进名单和明确对接价值总数中，方便后续重新跟进。

界面负责人使用虚构演示名「林舟」「小林」「Mia」。第一位负责人在界面使用别名映射，筛选仍匹配原始数据键，原 CSV 和数据字典保持不变。表格显示和 CSV 导出均使用界面别名。

## Local Mode 保存、恢复与导出

本节和下一节的磁盘保存说明适用于 Local Mode。Demo Mode 的相同按钮仅保存到当前访问者会话，页面会显示会话保存提示；刷新和服务重启后不能恢复。

`src/followup_store.py` 优先读取 `data/demo_tech_event_working.csv`；不存在时读取原始 `data/demo_tech_event.csv`。首次保存会创建 working 文件，后续保存更新该文件。原始 CSV 和原始数据字典均保持不变。

保存按 `attendee_id` 合并当前筛选结果的四个跟进字段，再检查完整记录、只读字段、合法枚举、编号与到场逻辑。保留全部 100 条报名记录。写入同目录临时文件成功后原子替换 working 文件，写入失败不覆盖已有文件。内容版本检查会拒绝已检测到的陈旧保存/恢复。持久化依赖磁盘 CSV，因此浏览器刷新和 Streamlit 重启均保留修改。working 文件损坏时显示错误，允许通过确认恢复回到基线，不会静默忽略错误数据。

「恢复演示数据」先显示影响说明；点击「确认恢复」才删除 working 文件并清除当前编辑器内容，重新加载 Demo；点击「取消」保留修改。该操作会丢弃已保存的演示修改，使用前应按需导出。

「导出最新跟进表」重新读取当前已保存的数据，导出全部明确对接价值对象，不受筛选影响。文件为 UTF-8 BOM CSV，包含九个中文业务列，使用界面负责人别名。未保存内容不会进入此按钮的导出。编辑器工具栏自带下载用于当前筛选表格，业务验收与交付请使用下方「导出最新跟进表」。

限制：CSV 适用于本地单用户流程，没有多人并发事务保障；多个标签页同时编辑应先刷新。原生表格的未提交单元格、未点击保存的编辑不持久化；手机或窄窗口需横向滚动，长备注建议进入单元格查看。当前版本没有自动保存或编辑历史。

## 活动复盘操作与规则（磁盘说明适用于 Local Mode）

流程：打开「活动复盘」→ 查看最新数据摘要 → 按需填写活动亮点、活动问题、渠道人工判断、重点关系、改进建议 → 点击「生成复盘草稿」→ 编辑正文 → 保存或导出。

数据入口与其他页面相同：存在 working CSV 时优先读取，否则使用原始 Demo。每次页面运行重新读取已保存数据；关系跟进页的未保存修改不会进入复盘。摘要覆盖四项活动结果、报名身份人数及占比、各渠道报名/到场/到场率与极值、前三方向，以及明确价值人数和四项跟进进度。

`src/review_generator.py` 使用真实统计与固定中文模板生成五章：活动概况、参与者与渠道观察、关键关系与跟进情况、活动亮点与问题、后续行动。概况的到场身份和全部报名身份分开统计，身份占比及前三方向以全部报名者为分母。渠道极值支持并列；无报名渠道显示暂无到场率且不参与极值比较。前三方向按人数降序，人数并列时使用活动观察页的既有方向顺序。暂不跟进对象仍计入明确价值总数，草稿另列其人数。

自动生成的内容标为「数据事实」，只比较人数、占比和状态；不会从到场率推断用户意愿、渠道质量或未到场原因。人工填写的内容保留原意，分别标为「人工观察」「人工判断」「人工补充」「人工建议」，作为运营人员的记录，不自动验证或背书。亮点或问题未填写时不虚构，二者均为空仅显示一处暂无补充。行动清单来自未完成跟进人数、人工重点关系与人工改进建议。自动统计不输出报名者姓名、机构、联系方式、跟进备注或个人动作；人工文本由使用者决定，导出前请确认正文内容。

草稿提供大文本编辑区，并提示「以下内容由结构化数据与人工输入生成，请在正式使用前人工确认。」点击正文，按 Ctrl+A 全选、Ctrl+C 复制。切换页面保留本次会话的人工表单和正文。点击「保存复盘草稿」将**当前编辑后的正文**保存到 `data/event_review_draft.md`；刷新或重启应用后重新读取已保存正文。五项表单本身仅保存在当前会话，刷新后为空，但已经整合并保存的观察仍保留在草稿中。刷新后再次生成时应重新填写需要保留的观察，或先复制所需文字。

非空草稿重新生成须点击「确认重新生成」，取消则保留编辑区。重新生成使用确认时的最新已保存活动数据，先替换编辑区，磁盘旧稿仍保留，只有再次保存才更新文件。如果本次会话生成后活动数据变更，页面提示草稿尚未同步；首次加载旧稿也提示其可能基于较早数据。不会自动把人工编辑覆盖成新统计。

`src/review_store.py` 只负责 UTF-8 Markdown 读取、内容版本检查和同目录临时文件原子替换。写入失败保留原稿并显示中文提示；遇到损坏文件阻止覆盖；检测到其他会话修改时拒绝陈旧保存，提示先导出当前编辑再刷新。仍适用于本地单用户，不提供多人事务、历史版本或自动保存。人工补充与草稿均不写入原始或 working CSV。

点击「导出 Markdown」先同步当前正文，弹窗内点击「下载 Markdown」下载 `创业者交流_活动复盘.md`，使用当前编辑区全文，**包括未保存的修改**，无须先保存。弹窗期间如需继续修改，请点击「返回编辑」，修改后再次导出；这样避免刚编辑便下载时取到上一版正文。不增加 PDF / Word 或外部模型服务依赖。本地草稿被 `.gitignore` 排除。

## 数据加载与错误处理

`src/data_loader.py` 从项目位置定位 CSV，使用 UTF-8 / UTF-8 BOM 读取，校验 13 个必要字段、表格列数、重复编号、核心空值、允许值及到场与跟进逻辑。机构和备注允许缺失；待跟进任务必须有负责人和具体动作。

文件不存在、编码错误、没有报名记录、必要字段缺失或存在业务矛盾时，页面显示中文错误并停止统计，避免错误数据变为看似可信的 KPI。加载仅在内存中去除首尾空格，不写回原文件。

字段定义见 [data/DATA_DICTIONARY.md](data/DATA_DICTIONARY.md)。当前合成 CSV 不应替换为含个人信息的真实名单后直接公开提交。
